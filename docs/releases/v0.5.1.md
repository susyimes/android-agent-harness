# v0.5.1 — Web4Agent exact-page safety

v0.5.1 is a security-focused, binary-compatible patch for the optional
`web4agent-android` AAR. It closes two upstream gaps found while integrating a
visible Web4Agent run into a product-owned global Stop surface.

## What changed

- The Harness WebChromeClient now handles `alert`, `confirm`, `prompt`, and
  `beforeunload` itself. Untrusted page dialogs are cancelled without creating
  a native Android dialog window above `Web4AgentBrowserActivity`. A bounded
  console policy event records the dialog type and origin only; message and
  prompt-default text are not retained.
- `web4agent_observe` and `web4agent_inspect` now return host-issued
  `pageEpoch`, `observationId`, and `documentFingerprint` values. DOM entries
  include `targetFingerprint`.
- Governed `web4agent_act` and `web4agent_eval` calls create one-use page leases
  before approval. Their `AgentEffectIntent.targetRef` binds the page epoch,
  observation, document fingerprint, and target fingerprint when applicable;
  the normal argument hash also covers the caller-supplied binding fields.
- After the approval token is consumed, the Android session rechecks the
  captured epoch and performs the document/target guard plus requested
  JavaScript/action in one WebView main-thread task. Page drift returns
  `STALE_TARGET`, `occurred=false`, and does not run the requested script,
  click, type, scroll, or navigation.
- Main-frame/history navigation, reload, meaningful DOM mutation, exact effect
  completion, Activity detach/attach, session close, and replacement invalidate
  outstanding observations and leases. A closed captured session cannot
  recreate its WebView or remove a newer replacement session.
- Document guards hash the complete serialized DOM plus live form-control
  state; input/change events also advance the host epoch. Approval cannot be
  reused after a value, checked state, enabled state, or selected option drifts.

## Migration for Web4Agent tool callers

Resolve the patch coordinate:

```groovy
implementation "dev.androidagent.harness:web4agent-android:0.5.1"
```

After `web4agent_observe` or `web4agent_inspect`, copy `observationId` and
`pageEpoch` into `observation_id` and `expected_page_epoch` on the next act or
eval. For click and type, also copy the selected element's
`targetFingerprint` into `target_fingerprint`. Observe or inspect again after
every action/eval and after any `STALE_TARGET` response.

Calls missing the new exact binding fail closed before approval/effect. A
custom session provider passed to the public `Web4AgentToolSet` constructor also
fails governed act/eval with `EXACT_EFFECT_UNSUPPORTED` unless it is backed by
the strict runtime session. Existing `Web4AgentRuntime.install/getInstance` and
`Web4AgentSession` JVM signatures are unchanged.

## Verification

- deterministic JVM approval-latch tests cover act and eval page drift,
  `STALE_TARGET`, zero backend calls, `occurred=false`, and successful retry
  only after a fresh observation;
- connected API 29 and API 34 coverage each pass 8/8 and exercise all four
  JavaScript dialog callbacks, same-selector DOM replacement during approval,
  session close/replacement, and the complete
  observe/read/inspect/act/eval/console/capture/finish loop;
- the release gate includes public ABI checks, JVM and Android unit tests,
  Android lint, local Maven publication, JVM/Android consumer smoke tests, and
  sample assembly; both `checkSdk` and `checkM0` pass.
