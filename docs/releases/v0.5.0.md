# v0.5.0 — visible, model-operated Web4Agent

v0.5.0 adds an independently authored Web4Agent Android capability and makes
the complete tool surface available to both SDK hosts and the Demo APK. The
model and user operate the same visible, session-keyed WebView.

## Highlights

- New publishable `web4agent-android` AAR with source JAR and independent-host
  Maven consumer coverage.
- Nine model-visible tools:
  `web4agent_open`, `web4agent_observe`, `web4agent_read`,
  `web4agent_inspect`, `web4agent_eval`, `web4agent_act`,
  `web4agent_console`, `web4agent_capture`, and `web4agent_finish`.
- Bounded DOM observation plus structured text, HTML, link, form, table, and
  metadata reads.
- CSS, XPath, and visible-text inspection with stable per-page element ids.
- Click, type, scroll, navigation, reload, and bounded wait actions.
- Free-form JavaScript evaluation and page actions remain behind the existing
  exact-effect approval protocol.
- Console collection and short-lived, session-scoped PNG capture payloads.
- Best-effort redaction of password and common secret-like form fields and
  attributes in structured observation, read, and inspect results.
- Secure WebView defaults: HTTPS-only navigation, no file/content access, no
  mixed content, no third-party cookies, Safe Browsing enabled, and no
  JavaScript bridge.
- Demo control-center entry plus registration of all nine tools in the real
  provider tool loop and sticky activation path.
- An Android instrumentation scenario exercises visible open, observe,
  inspect, type, click, wait, read, eval, console, capture, and finish in one
  session.

## Published coordinate

- Version: `0.5.0`
- Group: `dev.androidagent.harness`
- New AAR: `dev.androidagent.harness:web4agent-android:0.5.0`

All v0.4.0 JAR and AAR coordinates remain available at version `0.5.0`.

## Host integration

Create one `Web4AgentRuntime`, register `Web4AgentToolSet` in the same
`AgentSdk` request as the host's other tools, add
`Web4AgentGuidance.contextProvider()`, and include the nine Web4Agent names in
the Android sticky activation set. `web4agent_open` launches
`Web4AgentBrowserActivity` for the invocation's `sessionId`; every subsequent
tool resolves that same session.

The Demo APK already applies this composition. Its offline scripted provider
exposes the tools but does not synthesize web tool calls; select an
OpenAI-compatible provider/model with tool calling to exercise model-driven
web work.

## Privacy and compatibility

- Page content, DOM attributes, and console messages are untrusted run-time
  context and are explicitly marked as such in the Web4Agent guidance.
- Screenshots are not written to permanent storage by the AAR. Hosts supply a
  bounded raw-payload store; the Demo uses an in-memory exact-scope TTL store.
- Cookies and WebView process state follow Android System WebView behavior.
  Hosts are responsible for user disclosure and any explicit compatibility
  opt-ins.
- `Web4AgentConfiguration.compatible()` may allow HTTP, mixed content, or
  third-party cookies, but application network-security policy still applies.

## Deliberate limits

- MiniApp packaging and a native JavaScript bridge are not part of v0.5.0.
- Captured PNG bytes remain host-scoped; the SDK does not automatically expose
  raw pixels to a text-only provider.
- Repository-local Maven publication only.
- Debug APKs are development artifacts; production signing is not bundled.
