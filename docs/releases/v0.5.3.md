# v0.5.3 — Deterministic Web exact-effect consumer verification

v0.5.3 is a backward-compatible verification release. The production
Web4Agent runtime keeps the v0.5.2 exact dispatch fence and public API; this
release adds a legal, test-only seam so an independent Maven consumer can
deterministically prove the close/replacement race on the published bytes.

## What changed

- `web4agent-android` now publishes its official Gradle test-fixtures variant.
  Its capability is
  `dev.androidagent.harness:web4agent-android-test-fixtures:0.5.3`, selected
  from Android instrumentation tests with
  `testFixtures("dev.androidagent.harness:web4agent-android:0.5.3")`.
- `Web4AgentExactEffectTestHost` creates the real version-matched strict
  `AndroidWeb4AgentSession` inside the owning module. Consumers receive only
  the public `Web4AgentSession` and an opaque one-shot race controller; no
  internal session, hook, WebView, effect lease, or bypass API is exposed.
- A race gate can await `AFTER_GUARD_BEFORE_DISPATCH`, observe that the old
  session has been fenced, and release the call. It supports both close and
  same-id replacement, including a fresh-session retry after replacement.
- The fixture rejects non-debuggable hosts, bounds all waits/holds, salts and
  hashes its diagnostic effect token, and is explicitly headless. Visible
  BrowserActivity presentation generation/quiescence remains a separate test
  boundary.
- `sdk-android-consumer-smoke` consumes the published candidate Maven bytes,
  not source-project internals. Its isolation gate proves the variant exists
  only on `debugAndroidTestRuntimeClasspath`, is absent from
  `releaseRuntimeClasspath`, exists in its separate test-fixtures AAR and
  sources JAR, is absent from the production AAR, and does not duplicate the
  production session implementation.
- Publisher sidecar schema 2 records Gradle `variantCapabilities` in addition
  to Maven module coordinates and every file's SHA-256. This makes the
  test-only capability independently discoverable without pretending that it
  is a standalone POM coordinate.

## Consumer usage

```groovy
dependencies {
    implementation "dev.androidagent.harness:web4agent-android:0.5.3"
    androidTestImplementation testFixtures(
        "dev.androidagent.harness:web4agent-android:0.5.3"
    )
}
```

The test-fixtures capability depends on Gradle module metadata; it is not
representable in Maven POM metadata. Use a modern Gradle consumer and never add
the fixture with `implementation` or another production configuration.

## Verification

- The independent published-Maven Android consumer covers close and session
  replacement across back, forward, reload, click, and eval: ten captured
  `AFTER_GUARD_BEFORE_DISPATCH` windows per API level.
- On emulator API 29 and API 34, the two instrumentation tests each pass 2/2
  with zero skip/failure. Every old call returns `SESSION_CLOSED`,
  `occurred=false`, and zero marker change; replacement requires a fresh
  observation/approval before a new click succeeds.
- `checkConnectedSample` includes this consumer suite. `checkSdk` includes the
  dependency/byte isolation gate, and `checkM0` compiles the published-fixture
  Android-test consumer.
- The ordinary JVM ABI, Android lint, production Maven consumer, provenance,
  dirty-release rejection, clean-release sidecar, and artifact-hash gates
  remain required.

## Coordinates and boundary

- Version: `0.5.3`
- Group: `dev.androidagent.harness`
- Production module: `dev.androidagent.harness:web4agent-android:0.5.3`
- Test-only variant capability:
  `dev.androidagent.harness:web4agent-android-test-fixtures:0.5.3`
- Published classifiers: `test-fixtures.aar` and
  `test-fixtures-sources.jar` under the production module's version directory

Consume release bytes only from the new clean commit-bound Maven repository
named in `publisher-sidecar.json`; do not reuse or overwrite a 0.5.1/0.5.2
directory or consume the mutable candidate repository as release evidence.
