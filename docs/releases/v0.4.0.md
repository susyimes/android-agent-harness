# v0.4.0 — governed agent layers and complete sample control center

v0.4.0 implements milestones M9–M16 from the Mirror Android core-alignment plan. It turns the earlier bounded chat/Phone Use sample into a modular SDK with one run kernel, six platform-neutral business layers, optional Android adapters, and a product UI that exposes their real state and controls.

## Highlights

- Stable run policy, lifecycle events, deadline/cancellation, traces, replay, multi-dimensional budgets, and transactional sessions.
- Typed tool envelopes and a general approval protocol bound to exact effect arguments.
- CCP V2 context selection, evidence, routing, and prompt rendering.
- State Vault plus governed memory, skill, and persona candidate promotion/rollback.
- Stats, Todo, permissions, House/State, document, location, calendar, and notification adapters.
- Schedule, occurrence, revision, lease, WorkManager, Receiver, Heartbeat, Dream, Proactive, Cron, and LongTask support.
- Strict observe → one action → observe/finish Phone Use protocol.
- OpenAI-compatible SSE streaming, attachments, optional visual/sensor adapters, STT, ephemeral audio, and TTS.
- Home Brief and full Stats, Todo, State, Automation, Permissions, Debug/Replay, and Data & Retention product surfaces.
- Global Stop, background-off defaults, initiative/quiet-hour controls, redacted exports, retention, and exact-approved deletion.

## Compatibility and verification

- Android AARs and the sample require Android 10 / API 29 or newer.
- Kotlin ABI baselines cover all published JVM modules.
- Independent hosts consume the published JAR and AAR coordinates from the local Maven repository.
- `checkSdk` is the SDK/API/publication gate.
- `checkM0` is the full repository, lint, Android, and sample build gate.
- `checkConnectedSample` is the physical-device instrumentation gate.

## Migration notes

- Hosts using only the v0.3.0 `agent-sdk` facade can continue through compatibility defaults, but should adopt an explicit `AgentRunPolicy`, `TraceSink`, and CCP sources before enabling background or mutating tools.
- Tool results can still supply the legacy `content/isError` shape; the runtime converts it to a bounded envelope. New tools should return an explicit envelope.
- Agent-written durable memory should migrate to `MemoryCandidateSink`; enabled skills and persona state must use candidate governance.
- Phone Use hosts should enforce `StrictDeviceProtocol` and pass the latest `snapshot_id` on every action/finish.
- Android scheduling components have an empty library manifest. A host that uses boot restoration or visible LongTask service must declare the receiver/service and relevant permissions itself; the sample demonstrates this.

## Deliberate limits

- Repository-local Maven publication only.
- Debug APKs are development artifacts; production signing is not bundled.
- No GitHub, web, or arbitrary code-execution adapters.
- No external Obsidian vault-format compatibility.
- File-backed sample stores are app-private but are not encrypted databases.
