## Run-time user-supplied and user-granted material

Two things exist only at run time on the user's device and are never part of the repository, the APK, or any release artifact:

- **The API credential is user-supplied data, never shipped.** The sample app contains no credential and no default account; the user pastes their own credential in-app. It is stored exclusively in the app's private `SharedPreferences` file (`agent_harness_sample_prefs`, under the preference key `"openai_credential"`) on the device, is transmitted only as an `Authorization` header to the endpoint the user configured, and is removed by the in-app "Clear credential" button or by uninstalling the app. The `auditProvenance` guard enforces this at build time: any credential-shaped identifier assigned a quoted string literal fails the build, so a credential literal cannot enter the tree even disguised as a constant or test fixture.
- **The accessibility permission is a user-granted capability, not bundled data.** The APK declares the service, but declaring it grants nothing: the service is inert until the user manually enables it in the system accessibility settings, and the user can revoke it there at any time. While enabled, it reads the foreground window's node tree only when a phone-mode turn the user started requests a snapshot; the snapshot is text-only, size-bounded, held in memory for the turn, and never persisted by the harness. No screen content is captured as pixels, stored on disk, or included in any artifact this repository produces.

## Automated guard

The repository-native `auditProvenance` task fails when it finds:

- common secret/config/signing filenames anywhere outside ignored build/cache directories;
- embedded credential-like assignments, reference product namespaces, or private local paths in core, demo, sample, build, or documentation files; or
- non-XML binary resources in the Android sample.

This guard complements the manual inventory; it is not a general-purpose secret scanner. Publication should still review `git diff --cached` and the complete tracked-file list.
